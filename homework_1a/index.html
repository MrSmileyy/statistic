Why It Is Weak

With only 50,000 possible values for d, an attacker who knows Q and G can compute G, 2G, 3G, ... until obtaining Q. The curve remains the same as Bitcoin's: security collapses solely due to the key choice.

The private key d is a secret integer. The public key Q is not chosen at random, but is determined as a point on the curve by multiplying the generator point G by d.

Theoretical Background: Toy EC-ElGamal Scheme on secp256k1

1. The secp256k1 Curve

It is the Koblitz curve used by Bitcoin, defined over the field 𝔽p with p = 2256 - 232 - 977 and parameters a = 0, b = 7. The base point G generates a cyclic subgroup of prime order n ≈ 2256. All calculations use JavaScript's BigInt, because the Number type loses precision beyond 253.

2. Point Addition and Doubling

  • Addition (P ≠ Q): secant line through P and Q.
    s ≡ (yQ - yP) ⋅ (xQ - xP)-1 mod p
  • Doubling (P = Q): tangent line at P.
    s ≡ (3xP2 + a) ⋅ (2yP)-1 mod p

In both cases:

x3 ≡ s2 - xP - xQ,   y3 ≡ s(xP - x3) - yP   (mod p)

The modular inverse is computed using the extended Euclidean algorithm.

3. Double-and-Add

To compute k ⋅ P, k is read in binary from the most significant bit: at each bit the accumulator is doubled, and if the bit is 1, P is added. About log2(k) steps are needed instead of k - 1 additions.

4. Role of the Keys

The private key is an integer d; the public key is the point Q = d ⋅ G. Recovering d from Q is the Elliptic Curve Discrete Logarithm Problem (ECDLP). In this scheme d ∈ [1, 50000], so at most 50,000 additions of G are enough to find it.

5. EC-ElGamal Encryption

The text is split into blocks and each block is mapped onto a point M using Koblitz's method: x-coordinates x = m ⋅ 256 + j are tried until x3 + 7 is a square modulo p. Then, with a random nonce k:

C1 = k ⋅ G,    C2 = M + k ⋅ Q

The recipient, using their private key, computes:

C2 - d ⋅ C1 = M + kdG - dkG = M

and recovers the block as m = ⌊x / 256⌋.
